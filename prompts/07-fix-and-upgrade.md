# 07 - Fix and Upgrade an Existing AI-Generated Page

Use when you already have a page (usually generated by another model) that looks generic, has purple
gradients everywhere, animates too much and ignores accessibility. This prompt professionalizes it
without a rewrite.

---

## Prompt

```text
Read the Nova Vitral specification, sections 0.4, 1 (foundations), 2 (tokens), 6.1 to 6.3, 6.12,
9.5 (anti-patterns) and 9.6 (code review):
https://raw.githubusercontent.com/Pedro21062014/nova-design/main/nova-design.md

Read the surface and motion examples:
https://raw.githubusercontent.com/Pedro21062014/nova-design/main/examples/01-surfaces-glass.md
https://raw.githubusercontent.com/Pedro21062014/nova-design/main/examples/08-motion-interaction.md

Here is the current code: <paste or name files>

TASK: upgrade it to Nova Vitral without changing the information architecture.

Do this in order, and stop after each phase for review if I ask you to:

PHASE 1 - Tokenize
- Replace every hardcoded color, shadow, radius, blur and duration with the section 2 tokens.
- Map the existing shadcn variables to Nova Vitral tokens (spec 7.9, technique 1).
- Remove any @/lib/utils/colors file that duplicated what tokens now provide.

PHASE 2 - Fix the surfaces
- Replace flat translucent boxes with the vitral surface (fill + hairline + inner highlight).
- Ensure every glass element has an aurora, gradient or image behind it (spec 1.3 rule 1).
- Apply the nesting rule: inner panels lose blur and gain edge contrast.

PHASE 3 - Calm the motion
- Reduce every duration to the ladder in spec 6.1 (140 / 240 / 420 / 760ms).
- Make reveals fire once, 16px, ease-out, stagger capped at 400ms total.
- Delete decorative loops; keep at most one ambient animation per viewport.
- Add the reduced-motion path everywhere.

PHASE 4 - Add the missing states
- Every interactive element: hover, focus-visible, active, disabled, loading.
- Every data surface: loading, empty, error.
- Every form: inline validation with the fix, not just the problem.

PHASE 5 - Accessibility
- Focus rings on all interactive elements, correct roles and labels, AA contrast measured over the
  worst-case backdrop, keyboard walkthrough, target sizes, semantic HTML.

PHASE 6 - Content
- Replace placeholder copy with specific, benefit-led copy for <product and audience>.
- Remove fake metrics or label them honestly ("internal benchmark").

PHASE 7 - Performance
- Animate transform and opacity only; cap simultaneous backdrop-filter at six; lazy-load below the
  fold; virtualize long lists; remove unused dependencies.

Deliver for each phase:
- The diffs (not full files) unless a file changed more than 60 percent.
- A one-line rationale naming the spec section for each significant change.
- A short list of what you deliberately did not change and why.
```

## Triage table (what to fix first)

| Symptom in the current code | Root cause | Phase |
|---|---|---|
| Gray, muddy panels | glass without a background | 2 |
| Rainbow gradients | accent overuse | 1 and 2 |
| Everything fades in | no timing discipline | 3 |
| Animations replay on scroll up | `once: false` | 3 |
| No hover or focus states | components copied from a screenshot | 4 |
| Text unreadable on some scroll positions | contrast measured against a static backdrop only | 5 |
| "Lorem ipsum" or "Feature one" | generated placeholder content | 6 |
| Jank on scroll | box-shadow or blur animated | 7 |
| 400KB of JS for a landing page | client components everywhere | 7 |
| Layout shifts on load | fonts without fallback metrics, images without size | 7 |

## Follow-up prompts

**Diff-only mode:**

```text
From now on return unified diffs only, with three lines of context, and group them by phase.
```

**Regression guard:**

```text
Add a Playwright test that screenshots <routes> at 375 and 1440 in dark and light themes, and fails
on a pixel difference above 0.2 percent. This protects the visual upgrade from regressions.
```

**Before and after summary:**

```text
Write a short before/after summary for a pull request: what changed, which spec sections drove it,
what the visible improvement is, and what remains as follow-up work.
```
